# 学术智能问答

> 围绕一篇或多篇论文的自然语言问答：检索 → 增强 → 生成，答案必须能追溯到原文。

## 一、和普通知识库问答的区别

本项目原本就能「按知识库问答」，但学术场景有两个硬需求：

1. **按论文问**：我只想就这 3 篇论文提问，不希望库里其他文档混进来；
2. **逐篇交代**：我选了 3 篇，如果只有 1 篇有依据，必须告诉我另外 2 篇没有，
   而不是拿 1 篇的内容冒充 3 篇的结论。

因此这轮补了三件事：文档级范围、按篇配额检索、证据覆盖清单。

## 二、检索范围的三层

| 层级 | 传什么 | 语义 |
| --- | --- | --- |
| 知识库级 | `knowledgeBaseIds` | 这些库里的所有文档 |
| **论文级** | `documentIds` | 只在这些论文里检索（本期新增，优先级最高） |
| 全库 | 都不传 | 按用户可访问范围（个人库 + 所在团队库） |

论文级范围会先校验归属：不属于自己的文档一律按「不存在」处理，不会报权限错误暴露资源存在性。

## 三、按论文配额检索

**问题**：多篇论文同时检索时，如果只取全局 Top-K，最相关的那篇会吃掉全部名额。

实测：选 3 篇论文、`top_k=5` 时，A 篇 5 条、B/C 两篇 0 条 —— 模型看到的只有 A，
所谓「跨文献关联」自然做不出来。

**做法**：每篇论文单独查询，按 `ceil(top_k / 篇数)`（至少 2 条）保底，
再整体按相关度排序：

```
配额(5/3): A→2 条, B→2 条, C→1 条      ← 每篇都有发言权
```

代码：`server/app/services/vectorstore.py` 的 `_apply_document_quota()`（纯函数，有单测）。

## 四、跨论文作答约束

≥2 篇论文时，用户提示里会追加一段硬性要求（`prompts.MULTI_PAPER_RULES`）：

1. 先分别说明各篇怎么说，再给综合结论；
2. 各篇不一致时指出差异，分别标注引用编号；
3. **某篇没提到就写「《论文名》未提及」**，不许用其他论文的内容替它作答；
4. 跨论文的关联（继承、改进、互相矛盾）要明确点出。

## 五、证据覆盖清单

回答前的 `meta` 事件里带：

```json
{
  "documentIds": ["doc_a", "doc_b"],
  "coverage": [
    { "documentId": "doc_a", "documentName": "RAG原论文.pdf", "hits": 3 },
    { "documentId": "doc_b", "documentName": "RAG综述.pdf", "hits": 0 }
  ],
  "missingDocuments": ["RAG综述.pdf"]
}
```

前端据此在答案上方显示黄色提示：

> 所选的 1 篇论文中未找到相关依据：《RAG综述.pdf》——
> 上面的回答没有引用它们，不要当成这几篇的结论。

这是需求 8「证据不足提示」在**论文粒度**上的落地：不只是「整体没找到」，
而是「哪几篇找到了、哪几篇没找到」。

## 六、原文引用：论文名 + 章节 + 页码 + 片段

引用块长这样：

```
[2]（来源：RAG综述.pdf · 第 5 页 · A. Naive RAG · 相关度 0.78）
Naive RAG consists of indexing, retrieval and generation, ...
```

**章节是怎么来的**：解析阶段识别标题行（`server/app/services/parser.py`）：

| 写法 | 示例 |
| --- | --- |
| 数字编号 | `3 Method` / `4.2 Experimental Setup` |
| 罗马数字 | `II. RELATED WORK` |
| 单字母 | `A. Retrieval Source`（综述常见） |
| 中文 | `第 3 章 方法` / `三、实验结果` |
| 无编号固定词 | `Abstract` / `Introduction` / `Conclusion` |

- 标题状态**跨页延续**：某页没出现标题时沿用上一页所在章节；
- 进入 `References` 后停止识别，否则参考文献里的作者行
  （`A. Vaswani, ...`）会被当成章节标题 —— 实测踩过；
- 识别不到就用空串，前端不显示章节，不影响页码引用。

> 章节信息存在切片元数据里，**需要重新索引**才会生效（`dev.cmd --reindex`）。

## 七、接口

```
POST /api/chat/stream
{
  "conversationId": "conv_x",       // 可空，空则新建
  "content": "这几篇的检索方法有什么区别？",
  "knowledgeBaseIds": ["kb_1"],
  "documentIds": ["doc_a", "doc_b"],  // 可选：论文级范围
  "topK": 6,
  "scoreThreshold": 0.2,
  "modelId": "server:deepseek-chat"
}
```

SSE 事件顺序：`meta` → `sources` → `delta`… → `done`。

## 八、前端

检索范围面板（输入框上方「知识库」按钮）里新增「论文范围」区块：

- 列出已选知识库下的文档，勾选即限定范围；
- 显示每篇的片段数；未完成向量化的会标红；
- 换知识库时自动清空论文范围（避免残留不属于该库的 id）。

引用来源展开后显示「第 N 页 · 章节」，覆盖不足时答案上方有黄色提示。

## 十、已知限制

1. **章节识别依赖排版**：PDF 里标题与正文挤在同一行的（如 `RAG-Sequence Model The ...`）
   识别不到，此时只显示页码；
2. 章节信息需要重新索引后才写入向量库；
3. 论文级范围**不随会话保存**：刷新页面回到知识库范围，避免用户忘了自己钉死了某几篇；
4. 跨论文数量没有硬上限，但超过 5~6 篇时模型容易「平均化」，建议按主题分批问。
